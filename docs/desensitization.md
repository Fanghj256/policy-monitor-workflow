# 脱敏：把私人工作流变成可公开的模板

这套 workflow 是从一个真实监测项目里抽出来的，但**公开仓库里不能有真实项目痕迹**。脱敏不是「把文件名改掉」，而是同时处理内容、元数据和历史记录。

这篇清单按「先定原则，再逐项检查，最后跑验证」组织。

## 一、原则

1. **只保留方法，不保留数据。** 架构、脚本、模板、提示词可以公开；真实政策、内部判断、公司名、人名、联系方式不行。
2. **示例全部虚构。** 用 `示例市 / 示例区 / 示例部门 / 示例企业 / 示例同事`；域名用保留的 `example.gov.cn` / `example.org`。
3. **路径不落地。** 仓库里只出现相对路径；不出现本机盘符、用户目录、项目根目录。
4. **凭据零容忍。** 访问密钥、会话凭据、口令、请求头里的认证信息，一律不进仓库、不进日志、不进截图。
5. **历史也要干净。** 如果从旧仓库复制过文件，`.git` 历史可能还留着旧内容；公开前要么新历史，要么彻底清理。

## 二、逐项检查

### 1. 人名、公司名、机构名

| 可公开 | 需替换 | 禁止 |
|---|---|---|
| 角色：监测员、研究员、签发人 | 真实姓名、花名、邮箱前缀 | 身份证号、手机号、住址 |
| 示例市、示例区、示例部门 | 真实政府机构、部门、园区 | 真实企业内部项目名、产品名 |
| 示例企业、示例同事 | 真实公司、客户、供应商 | 真实合同、报价、客户名单 |

检查方法：

- 通读 README、docs、prompts、templates；
- 搜索常见姓氏/名字（人工，不列具体名单）；
- 搜索 `@` 邮箱、`1[3-9]` 手机号、`0\d{2,3}-` 座机；
- 搜索公司后缀：`有限公司`、`集团`、`科技股份` 等，确认都是「示例」。

### 2. 本地路径与机器信息

需要清理：

- 盘符路径、用户目录、桌面/下载目录；
- 项目根目录的绝对路径；
- 日志里的当前工作目录；
- 截图/录屏里的文件管理器路径；
- Jupyter notebook 的 `cwd`、输出单元格。

检查命令（在仓库根目录跑）：

```bash
rg -n "[A-Za-z]:[\\\\/]" .
rg -n "/Users/|/home/|/mnt/|/Volumes/" .
rg -n "Desktop|Downloads|Documents" .
```

如果命中，改成相对路径或 `examples/...`。

### 3. 域名、链接、联系方式

- 示例域名只用 `example.gov.cn`、`example.org`、`example.com`；
- 不出现真实政策库、内部 wiki、飞书/钉钉文档、网盘分享链接；
- 不出现带签名的下载链接（链接本身可能含凭据）；
- 不出现真实邮箱、电话、地址、邮编；
- 截图里的浏览器地址栏也要检查。

检查命令：

```bash
rg -n "https?://" .
rg -n "@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}" .
```

逐条看：保留 `example.*` 和许可证链接，其余替换或删除。

### 4. 凭据与会话信息

以下内容**任何情况下都不要提交**：

- 访问密钥、接口密钥、云服务密钥；
- 登录后的会话凭据、请求头里的认证字段；
- 账号口令、二次验证备份码；
- 带签名的 URL、临时上传地址；
- 浏览器导出的登录状态文件。

检查命令：

```bash
rg -n "api[_-]?key|authorization|bearer|BEGIN .*PRIVATE KEY" .
rg -n "AKIA[0-9A-Z]{16}|sk-[A-Za-z0-9]{20,}" .
```

即使命中的是示例占位符，也建议改成 `YOUR_KEY_HERE` 并说明「只放在本地配置」。

### 5. 真实数据

禁止提交：

- 真实政策库的 `index.json`、条目 JSON、报告成品；
- 真实原文 HTML、PDF、附件；
- 真实运行日志、错误堆栈里的内部 URL；
- 真实工作台的截图、录屏、数据库导出；
- 真实申报材料、企业名单、评审意见。

可以提交：

- 8 条虚构条目；
- 4 个虚构 HTML 快照；
- 由 demo 生成的 `examples/outputs/`；
- 模板和提示词。

检查方法：

```bash
find . -name "*.json" -o -name "*.md" -o -name "*.html" | ...
```

逐个打开 `examples/` 以外的数据文件；`data/`、`outputs/` 应该被 `.gitignore` 忽略。

### 6. 内部判断

以下内容即使没有名字，也可能敏感：

- 「某业务线优先级最高」「某客户必须拿下」；
- 内部风险评级、竞争策略、报价策略；
- 对具体企业/人物的负面评价；
- 未公开的申报计划、政府沟通记录；
- 真实项目的周报结论、行动建议。

公开版只保留**方法**：

- 怎么分级、怎么排序、怎么核验；
- 报告模板的空结构；
- 提示词的约束；
- 虚构示例的判断过程。

### 7. 代码与配置注释

注释里最容易漏：

- `# 某某项目专用`、`# 按某领导要求`；
- 真实接口地址、内部系统名；
- 调试用的真实 ID、手机号、邮箱；
- 「TODO: 问某某」；
- 临时绕过逻辑（如忽略证书、关闭校验）。

检查：

```bash
rg -n "TODO|FIXME|HACK|临时|内部|真实|生产" .
```

逐条判断：是通用说明，还是项目痕迹。

### 8. Git 历史与提交信息

如果仓库从旧项目复制而来：

- `.git` 目录可能保留旧提交、旧文件名、旧作者信息；
- 删除文件不等于删除历史；
- 提交信息可能含内部项目名、人名、工单号。

处理方式（由仓库维护者统一做，不在本仓库内执行）：

1. 公开版使用全新历史；
2. 或对历史做重写/清理后再发布；
3. 发布前跑 `git log --stat`、`git log -p` 抽查；
4. 检查 `.git/config` 里的远程地址和用户名。

### 9. 文档元数据

Word/PDF/PPT 可能带：

- 作者、公司、最后修改人；
- 修订记录、批注、隐藏文字；
- 自定义属性、模板路径；
- 嵌入的 Excel/图片。

公开前：

- 导出为纯 Markdown 或清理元数据后的 PDF；
- 删除批注和修订；
- 检查图片 EXIF（GPS、设备、时间）；
- 截图打码路径、账号、头像。

### 10. 图片与截图

- 不出现真实姓名、公司 logo、内部系统界面；
- 不出现浏览器标签页里的内部文档标题；
- 不出现二维码、条形码、分享链接；
- 不出现任务栏/桌面文件名；
- 示例图尽量用生成的占位图或纯文字图。

## 三、替换规则

| 类型 | 替换为 | 说明 |
|---|---|---|
| 城市 | 示例市 | 不要用真实城市名 |
| 区/县 | 示例区 | 不要用真实行政区 |
| 部门 | 示例市××局 / 示例区××局 | 保留职能，不保留真实名称 |
| 企业 | 示例智能科技有限公司 / 示例制造企业 | 不要用真实公司名 |
| 人物 | 示例同事、示例负责人 | 不要用真实姓名/花名 |
| 域名 | `example.gov.cn` / `example.org` | 保留域名，不解析真实站点 |
| 文号 | 示府办〔2026〕18号 等 | 虚构但格式合理 |
| 日期 | 2026-11 的连续日期 | 避免与真实报告重合 |
| 联系方式 | 不写，或写「示例受理窗口」 | 不写真实电话/邮箱 |

## 四、发布前验证

### 1. 跑 demo

```bash
python scripts/run_pipeline.py --demo
```

确认：

- 8 条条目、4 个信源、3 份报告；
- 没有网络请求；
- 输出里没有绝对路径；
- 所有机构/人名/企业都是「示例」。

### 2. 编译检查

```bash
python -m py_compile scripts/common.py scripts/fetch.py scripts/parse.py scripts/index.py scripts/report.py scripts/run_pipeline.py
```

### 3. 文本扫描

```bash
# 本地路径
rg -n "[A-Za-z]:[\\\\/]|/Users/|/home/" .

# 真实域名（人工看结果）
rg -n "https?://" .

# 凭据形态
rg -n "api[_-]?key|authorization|bearer|BEGIN .*PRIVATE KEY" .

# 电话/邮箱
rg -n "@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}" .
rg -n "1[3-9][0-9]{9}" .
```

### 4. 人工通读

按顺序读：

1. `README.md`
2. `docs/*.md`
3. `prompts/*.md`
4. `templates/*.md`
5. `examples/items/*.json`
6. `examples/sources/*.html`
7. `sources/sources.example.yaml`
8. `scripts/*.py` 的注释

每读到一个专有名词，问一句：这是真实的吗？如果是，替换。

### 5. 检查 `.gitignore`

确认以下内容不会进仓库：

```text
data/
outputs/
*.local.yaml
.env
```

`examples/outputs/` 是例外，它是 demo 成品，可以提交。

## 五、如果已经泄露

1. **先止损**：撤销/轮换相关凭据，关闭分享链接；
2. **再清理**：删除文件、清理历史、重新发布；
3. **后复盘**：记录泄露路径（截图/日志/提交），补检查项；
4. 如果涉及个人信息或客户数据，按组织流程通知相关方。

删除一个文件不等于删除历史；公开仓库要假设「所有人都已经 clone 过」。

## 六、可以保留的内容

- 通用的六段式架构；
- 脚本和选择器实现；
- 报告模板的空结构；
- 提示词的约束和输出格式；
- 虚构的 8 条示例；
- 信源配置的字段说明；
- 许可和安全文档。

一句话：**保留「怎么做」，去掉「为谁做、做了什么、结果如何」。**
